## 1. 이 앱이 하는 일 (큰 그림)

**LinkMaker**는 "긴 주소를 짧은 주소로 바꿔 주고, 그 짧은 링크가 몇 번·누구에게 클릭됐는지
통계를 보여주는" 서비스입니다. (Bitly 같은 서비스의 미니 버전)

### 사용자 입장에서의 흐름

```
1) 사용자가 긴 URL을 붙여넣는다:  https://example.com/very/long/path?a=1&b=2
2) 앱이 짧은 링크를 만들어 준다:   https://우리도메인/go/abc123
3) 누군가 그 짧은 링크를 클릭하면:
   - 앱이 클릭을 "기록"하고 (언제, 어느 나라, 어떤 기기, 봇인지 사람인지 …)
   - 진짜 목적지(원래 긴 URL)로 보내 준다.
4) 만든 사람은 대시보드에서 통계를 본다: 총 클릭수, 국가별/기기별/시간대별 그래프 등.
```

### 이 앱의 특별한 점 (설계 철학)

1. **로그인이 없다.** 링크를 만들면 "익명 작업공간(workspace)"이 자동으로 생기고,
   `/d/<비밀토큰>` 형태의 대시보드 링크를 받습니다. 그 링크만 있으면 어느 기기에서든
   자기 대시보드에 다시 들어올 수 있습니다.
2. **짧은 링크는 '주소'와 '목적지'가 분리**되어 있습니다. `/go/abc123`(주소)은 그대로 두고
   목적지 URL만 나중에 바꿀 수 있습니다. → 이미 뿌린 링크를 그대로 두고 목적지를 교체 가능,
   그동안 쌓인 통계도 유지됩니다.
3. **개인정보를 최소한만** 다룹니다. 방문자의 원본 IP는 저장하지 않고, 매일 바뀌는
   해시값으로 "대략 몇 명"만 추정합니다.
4. **무료 서버 환경**에서도 잘 돌아가도록(잠든 DB 깨우기 등) 신경 썼습니다.

## 2. 먼저 알아야 할 기초 개념

### 2.1 웹은 어떻게 동작하나 (요청과 응답)

웹은 기본적으로 **요청(request) → 응답(response)** 의 반복입니다.

- **브라우저**(크롬 등)가 "이 주소 주세요"라고 **요청**을 보냅니다.
- **서버**(우리 코드가 돌아가는 컴퓨터)가 그 요청을 처리하고 **응답**(HTML, 데이터, 이미지 등)을 돌려줍니다.

요청/응답에는 부가 정보인 **헤더(header)** 가 붙습니다. 예:
- `User-Agent`: 브라우저가 "나는 크롬이야, 안드로이드야" 하고 자기를 소개하는 문자열.
- `Accept-Language`: "나는 한국어를 선호해"(`ko`) 같은 언어 정보.
- `Cookie`: 이전에 서버가 브라우저에 저장해 둔 작은 값(로그인 상태 등).

응답에는 **상태 코드(status code)** 라는 숫자가 붙습니다. 자주 보는 것들:
- `200` 성공, `201` 새로 만들어짐
- `302` 다른 주소로 이동(리다이렉트)
- `400` 잘못된 요청, `401` 인증 안 됨, `404` 없음
- `429` 너무 많이 요청함(속도 제한), `503` 일시적으로 사용 불가

### 2.2 서버와 클라이언트

- **클라이언트(client)** = 사용자의 브라우저. 화면을 그리고, 버튼 클릭에 반응합니다.
- **서버(server)** = 우리 코드가 돌아가는 원격 컴퓨터. DB에 접근하고, 비밀값을 다룹니다.

**중요:** 비밀값(예: DB 비밀번호, 서명 키)은 **절대 클라이언트로 보내면 안 됩니다.**
브라우저로 간 것은 누구나 열어볼 수 있기 때문입니다. 그래서 이 프로젝트는 서버 전용 파일에
`import "server-only";` 를 붙여, 실수로 브라우저 코드에 섞이면 빌드가 실패하도록 막습니다.

### 2.3 JavaScript / TypeScript 기초 문법

이 프로젝트는 **TypeScript**로 짜여 있습니다. TypeScript = JavaScript + "타입(자료형)".

```ts
// 변수 선언: const(변경 불가) / let(변경 가능)
const name = "링크메이커";   // 문자열(string)
let count = 0;               // 숫자(number)
count = count + 1;           // let이라 바꿀 수 있음
count += 1;                  // 위 줄의 줄임말 (count = count + 1)

// 타입 표기: 변수/매개변수 뒤에 : 타입
const age: number = 20;
function greet(who: string): string {   // string을 받아 string을 돌려주는 함수
  return "안녕, " + who;
}

// 배열과 객체
const list: number[] = [1, 2, 3];          // 숫자 배열
const user = { id: "a1", name: "홍길동" };  // 객체(키-값 묶음)
user.name;                                  // "홍길동" (점으로 접근)

// 참/거짓과 조건
if (count > 0) { /* ... */ } else { /* ... */ }

// 화살표 함수 (익명 함수를 짧게)
const double = (n: number) => n * 2;
```

**자주 나오는 헷갈리는 기호들** (아주 중요):

| 기호 | 이름 | 뜻 | 예 |
|---|---|---|---|
| `?.` | 옵셔널 체이닝 | 앞이 없으면(null/undefined) 에러 대신 undefined | `user?.name` |
| `??` | null 병합 | 왼쪽이 null/undefined면 오른쪽 사용 | `name ?? "익명"` |
| `!` | 부정 / 아님 | 조건을 뒤집음 | `if (!found)` = 없으면 |
| `\|\|` | 또는 | 왼쪽이 거짓 같으면 오른쪽 | `a \|\| "기본값"` |
| `&&` | 그리고 | 왼쪽이 참이면 오른쪽 | `ok && doIt()` |
| `...` | 전개(spread) | 배열/객체를 펼침 | `{ ...a, b: 2 }` |
| `` `${x}` `` | 템플릿 문자열 | 문자열 안에 변수 삽입 | `` `/go/${slug}` `` |

`?.` 과 `??` 는 이 코드 전체에서 아주 자주 나옵니다. 예:
```ts
const first = forwarded.split(",")[0]?.trim();  // 0번째가 없을 수도 있어 ?. 로 안전하게
return realIp ?? null;                          // realIp가 없으면 null
```

### 2.4 비동기(async/await) — 가장 헷갈리는 부분

DB 조회, 네트워크 요청처럼 **시간이 걸리는 일**은 "결과가 나중에 온다"는 뜻에서
**비동기(asynchronous)** 라고 합니다.

- `async` 를 붙인 함수는 "이 안에 기다릴 일이 있다"는 표시입니다.
- `await` 는 "이 일이 끝날 때까지 기다렸다가 결과를 받아라"는 뜻입니다.

```ts
async function getLink() {
  // await: DB가 결과를 줄 때까지 기다림. 그동안 서버는 다른 일을 할 수 있음.
  const link = await prisma.link.findUnique({ where: { slug: "abc123" } });
  return link;  // 여기서는 link가 이미 도착해 있음
}
```

`Promise`(약속)는 "나중에 값을 주겠다는 약속"입니다. `await`는 그 약속이 지켜질 때까지 기다립니다.
여러 개를 **동시에** 기다리려면 `Promise.all([...])` 를 씁니다(하나씩 기다리는 것보다 빠름).

```ts
// 세 개를 동시에 조회하고, 셋 다 오면 배열로 받음
const [a, b, c] = await Promise.all([queryA(), queryB(), queryC()]);
```

### 2.5 Next.js와 React (서버 컴포넌트 vs 클라이언트 컴포넌트)

- **React**: 화면을 "컴포넌트(부품)"라는 함수 단위로 만드는 라이브러리.
  컴포넌트는 **JSX**(HTML처럼 생긴 문법)를 돌려줍니다.
- **Next.js**: React로 웹앱을 편하게 만들게 해 주는 틀(framework). 이 프로젝트는 Next.js의
  **App Router** 방식을 씁니다(폴더 구조가 곧 주소가 됨. 예: `src/app/(marketing)/page.tsx` → `/`).

App Router에는 두 종류의 컴포넌트가 있습니다. **이 구분이 매우 중요합니다.**

| | 서버 컴포넌트 (기본) | 클라이언트 컴포넌트 |
|---|---|---|
| 표시 | 파일 맨 위에 아무 표시 없음 | 파일 맨 위에 `"use client";` |
| 어디서 실행 | 서버에서만 | 브라우저에서 |
| 할 수 있는 것 | DB 직접 조회, 비밀값 사용 | 클릭·입력 반응, `useState` 등 |
| 못 하는 것 | 버튼 클릭 반응(상호작용) | DB 직접 조회 |

**규칙:** 데이터를 불러와 화면을 그리는 페이지는 서버 컴포넌트로,
버튼·폼처럼 사용자와 상호작용하는 작은 부품은 클라이언트 컴포넌트로 만듭니다.
서버 컴포넌트가 데이터를 불러와서, 클라이언트 컴포넌트에 넘겨주는 구조입니다.

React에서 자주 쓰는 것들:
- `useState`: 컴포넌트가 기억하는 "상태" 값(예: 창이 열렸는지). 바뀌면 화면이 다시 그려짐.
- `useEffect`: 화면이 그려진 뒤(또는 특정 값이 바뀔 때) 실행할 코드.
- **props**: 부모 컴포넌트가 자식에게 넘겨주는 값(함수의 인자와 비슷).

### 2.6 데이터베이스와 Prisma(ORM)

- **데이터베이스(DB)**: 데이터를 "표(table)" 형태로 저장하는 창고. 이 앱은 **PostgreSQL**을 씁니다.
  표 = 엑셀 시트, 행(row) = 한 줄, 열(column) = 항목.
- **ORM**: 데이터베이스를 SQL 대신 "일반 코드"로 다루게 해 주는 도구. 이 앱은 **Prisma**를 씁니다.

```ts
// SQL로는:  SELECT * FROM links WHERE slug = 'abc123';
// Prisma로는:
const link = await prisma.link.findUnique({ where: { slug: "abc123" } });
```

DB의 표 설계도는 `prisma/schema.prisma` 파일에 있습니다. 이 앱의 표들:
- **User**(작업공간) — 링크와 캠페인을 소유
- **Link**(짧은 링크) — 목적지, 슬러그, UTM 등
- **LinkEvent**(클릭 1건 기록) — 통계의 원천 데이터
- **LinkImage**(링크에 붙은 이미지), **Campaign**(링크 묶음), **Setting**(앱 설정값)

표들 사이 관계: `User 1명 → Link 여러 개 → LinkEvent 여러 개`.

### 2.7 쿠키·세션·JWT

- **쿠키(cookie)**: 서버가 브라우저에 저장해 두는 작은 값. 다음 요청 때 자동으로 서버에 딸려 옵니다.
- **세션(session)**: "이 브라우저는 이 작업공간의 주인이다"라는 로그인 상태 같은 것.
- **JWT(JSON Web Token)**: `{ 내용 + 서명 }` 형태의 토큰. 서명은 **비밀 키로만** 만들 수 있어서,
  누가 내용을 위조하면 서명 검증에서 걸립니다. 이 앱은 세션을 JWT로 만들어 쿠키에 담습니다.

이 앱의 세션 쿠키 이름은 `lm_session` 이고, 옵션은 이렇습니다(보안상 중요):
- `httpOnly`: 자바스크립트로 못 읽게(탈취 방지)
- `secure`: 운영 환경에선 HTTPS에서만 전송
- `sameSite: "lax"`: 다른 사이트에서의 요청엔 쿠키를 제한(CSRF 완화)

### 2.8 환경변수와 비밀값

**환경변수(environment variable)**: 코드 밖(서버 설정)에 저장하는 값. 비밀번호처럼 코드에
직접 쓰면 안 되는 것을 담습니다. 코드에서는 `process.env.이름` 으로 읽습니다.

이 앱에서 꼭 필요한 것은 `DATABASE_URL`(DB 접속 주소) 하나뿐입니다. 나머지 비밀값
(`AUTH_SECRET`, `ANALYTICS_SALT`)은 없으면 서버가 자동 생성해 DB에 저장합니다
(`src/lib/secrets.ts`). 덕분에 DB만 있으면 바로 돌릴 수 있습니다.

### 2.9 시간대(UTC vs 한국시간)

- 컴퓨터는 시간을 **UTC**(세계 표준시)로 저장합니다.
- 한국은 UTC보다 **9시간 빠릅니다**(KST = UTC+9).

DB에는 UTC로 저장하지만, 대시보드는 한국 시간으로 보여야 합니다. 그래서 통계를 낼 때
UTC 값에 +9시간(=540분)을 더해 "현지 시각"으로 바꾼 뒤 날짜/시간별로 묶습니다.
이 계산은 `src/lib/stats.ts` 와 `src/lib/utils.ts`(`displayOffsetMinutes`)에 있습니다.

## 3. 폴더 구조 지도

```
linkmaker/
├─ prisma/
│  └─ schema.prisma        ← DB 표 설계도 (데이터 구조의 출발점)
├─ src/
│  ├─ app/                 ← 페이지와 API (폴더 구조 = 웹 주소)
│  │  ├─ (marketing)/      ← 랜딩(홈) 페이지들. 괄호 폴더는 주소에 안 나타남(그룹)
│  │  ├─ (dashboard)/      ← 로그인 후 대시보드 화면들
│  │  ├─ go/[slug]/        ← 짧은 링크 클릭 처리 (이 앱의 심장부)
│  │  ├─ d/[token]/        ← 대시보드 링크로 세션 열기
│  │  ├─ s/[slug]/         ← 공개 통계 페이지(토큰으로 접근)
│  │  └─ api/              ← 데이터 API (CSV 내보내기, QR, 링크 생성 등)
│  ├─ components/          ← 화면 부품(React 컴포넌트)
│  │  ├─ dashboard/        ← 대시보드 전용 부품
│  │  ├─ charts/           ← 그래프 부품
│  │  └─ ui/               ← 버튼·카드 등 기본 UI 부품
│  └─ lib/                 ← 핵심 로직(화면이 아닌 "기능")
│     ├─ actions/          ← 서버 액션(버튼이 호출하는 서버 함수)
│     ├─ auth.ts           ← 세션/쿠키/JWT
│     ├─ url.ts            ← URL 검증(SSRF 방어)
│     ├─ analytics.ts      ← 클릭에서 정보 뽑기
│     ├─ stats.ts          ← 통계 집계(SQL)
│     ├─ links.ts          ← 링크 만들기/수정/삭제
│     └─ i18n/             ← 다국어(한/영)
```

`[slug]`, `[token]` 처럼 **대괄호**로 된 폴더는 "값이 바뀌는 자리"입니다.
예: `/go/abc123` 에서 `abc123`이 `slug`가 됩니다.

## 4. 추천 학습 순서

아래 순서로 읽으면 "데이터 → 로직 → 화면" 순으로 자연스럽게 이해됩니다.

1. **데이터 구조**: `prisma/schema.prisma` (표들이 어떻게 생겼는지)
2. **가장 작은 도구들**: `src/lib/slug.ts`, `src/lib/nanoid.ts`, `src/lib/utils.ts`
3. **보안 기초**: `src/lib/url.ts`(SSRF), `src/lib/ratelimit.ts`(속도 제한), `src/lib/bot.ts`(봇 탐지)
4. **인증**: `src/lib/secrets.ts` → `src/lib/auth.ts`(세션/JWT)
5. **핵심 흐름**: `src/app/go/[slug]/route.ts`(클릭 처리) — [5장](#5-핵심-링크-클릭-1건의-여정-데이터-흐름)과 함께
6. **분석**: `src/lib/analytics.ts` → `src/lib/stats.ts`(집계 SQL·시간대)
7. **링크 CRUD**: `src/lib/links.ts` → `src/lib/actions/*.ts`
8. **화면**: `src/app/(marketing)/page.tsx`(랜딩) → 대시보드 페이지들 → 컴포넌트들
9. **다국어**: `src/lib/i18n/*`

## 5. 핵심: 링크 클릭 1건의 여정 (데이터 흐름)

이 앱을 이해하는 가장 좋은 방법은 **클릭 한 번이 어디를 거치는지** 따라가는 것입니다.
누군가 `https://우리도메인/go/abc123` 을 클릭했다고 합시다.

```
[브라우저] "/go/abc123 주세요" 요청
     │
     ▼
[src/app/go/[slug]/route.ts]  ← 이 파일의 GET 함수가 실행됨
     │
     ├─ 1) 속도 제한 확인 (src/lib/ratelimit.ts)
     │      같은 IP가 1분에 120번을 넘었으면 → 429로 거절
     │
     ├─ 2) DB에서 slug="abc123" 링크 찾기 (src/lib/prisma.ts)
     │      - 무료 DB가 잠들어 있으면 몇 초 걸릴 수 있어 재시도(withRetry)
     │      - 없으면/비활성/만료면 → /link-unavailable 안내 페이지로 이동
     │
     ├─ 3) 목적지 URL에 UTM 태그 붙이기 (src/lib/url.ts applyUtm)
     │
     ├─ 4) 클릭 정보 모으기 (src/lib/analytics.ts collectEvent)
     │      - User-Agent 분석 → 브라우저/OS/기기
     │      - 봇 판별 (src/lib/bot.ts)
     │      - 방문자 해시 만들기 (원본 IP는 저장 안 함)
     │      - DB의 link_events 표에 한 줄 추가
     │      ※ 이 기록은 최대 2.5초만 기다림 → 느려도 이동을 막지 않음
     │
     ▼
[브라우저] 302 응답 → 진짜 목적지(원래 긴 URL)로 이동
```

나중에 만든 사람이 대시보드를 열면:

```
[src/app/(dashboard)/dashboard/page.tsx]  (서버 컴포넌트)
     │
     ├─ requireUser()로 로그인 확인 (src/lib/auth.ts)
     ├─ getDashboardData(userId) 호출 (src/lib/stats.ts)
     │      └─ link_events 표를 여러 각도로 세고 묶음(SQL)
     │         (총 클릭, 국가별, 기기별, 시간대별 …)  ← 시간대는 한국시간으로 변환
     ▼
   화면에 KPI 카드 + 그래프로 표시 (src/components/*)
```

이 흐름을 머릿속에 넣고 6장의 파일들을 읽으면 "이 코드가 전체에서 어디쯤인지" 감이 잡힙니다.

## 6. 파일별 정독

각 파일마다 **① 무슨 파일인가 ② 어떤 개념을 배우나 ③ 눈여겨볼 부분** 순으로 정리했습니다.

### 6.1 데이터의 뼈대

#### `prisma/schema.prisma` — DB 표 설계도
- **무슨 파일:** 앱이 쓰는 모든 DB 표(User, Link, LinkEvent, …)의 구조를 정의.
- **배우는 개념:** 표/열/기본키(`@id`)/고유값(`@unique`)/관계(1:다)/색인(`@@index`)/
  캐스케이드 삭제(`onDelete: Cascade`, 부모가 지워지면 자식도 삭제).
- **눈여겨볼 부분:** `LinkEvent`에 `date`, `hour`, `dayOfWeek`를 **미리 뽑아 저장**해 둔 것.
  이렇게 하면(비정규화) 통계를 낼 때 매번 계산하지 않아 빨라집니다. `visitorHash`는
  "되돌릴 수 없고 매일 바뀌는" 방문자 추정용 값(원본 IP 아님).
- **직접 확인:** `model Link` 안의 `slug @unique` 와 `destinationUrl`을 보세요.
  "주소(slug)와 목적지(destinationUrl)가 분리"되어 있어 목적지만 바꿀 수 있는 구조입니다.

#### `src/lib/prisma.ts` — DB 연결 하나 만들기
- **배우는 개념:** 왜 연결을 `globalThis`에 저장해 재사용하는가(개발 중 파일이 자주
  다시 로드돼도 연결이 쌓이지 않게). `warmDb()`는 잠든 DB를 깨우는 가벼운 쿼리.

### 6.2 가장 작은 도구들

#### `src/lib/nanoid.ts` — 무작위 ID 생성기
- **배우는 개념:** 암호학적 난수(`randomBytes`), 비트마스크, "거절 표집(rejection sampling)".
  특정 글자가 더 자주 나오는 편향을 없애려고, 범위를 벗어난 난수는 버리고 다시 뽑습니다.

#### `src/lib/slug.ts` — 슬러그(짧은 주소 끝부분) 생성·검증
- **배우는 개념:** 정규식(`SLUG_PATTERN`)으로 허용 문자 제한, 예약어(앱 경로와 겹치면 안 됨).
  헷갈리는 글자(0/O, 1/l/I)를 뺀 알파벳을 쓰는 이유(사람이 따라 적기 쉽게).

#### `src/lib/utils.ts` — 잡다한 도우미
- **배우는 개념:** `cn()`(CSS 클래스 합치기), `appUrl()`(환경에 따라 도메인 결정),
  `formatNumber`/`formatDate`, 그리고 **`displayOffsetMinutes()`**(UTC→한국시간 시차 계산).
  `Intl.DateTimeFormat`으로 실제 시대의 벽시계 시각을 구해 시차를 냅니다.

### 6.3 보안 기초 (아주 중요)

#### `src/lib/url.ts` — 목적지 URL 검증 (SSRF/오픈 리다이렉트 방어)
- **왜 중요:** 사용자가 넣은 주소를 그대로 믿으면 위험합니다.
  - `javascript:` 같은 주소 → XSS(악성 스크립트 실행) 위험 → **http/https만 허용**.
  - `127.0.0.1`, `localhost`, 사설망(10.x, 192.168.x), 클라우드 메타데이터(169.254.169.254)
    → 서버 내부를 훔쳐보게 만드는 SSRF 위험 → **내부 주소 차단**.
- **눈여겨볼 부분:** IP를 8/16진수로 위장하는 우회(`0x7f000001`)나 끝점 dot(`localhost.`)까지
  막는 부분. 반대로 `01net.com` 같은 정상 도메인은 막지 않도록 "알파벳 TLD가 없을 때만"
  숫자 IP 규칙을 적용합니다.

#### `src/lib/ratelimit.ts` — 속도 제한 (남용 방지)
- **배우는 개념:** "고정 윈도우" 방식. `Map`으로 키(IP)별 카운터를 세고, 창이 끝나면 초기화.
  이 카운터는 **서버 메모리**에만 있어 서버가 여러 대면 정확하지 않다는 한계도 이해하세요.

#### `src/lib/request.ts` — 요청에서 IP·위치 뽑기
- **배우는 개념:** 프록시/CDN 뒤에 있을 때 진짜 IP를 어디서 읽나. 플랫폼이 넣는
  `x-real-ip`가 신뢰 가능(클라이언트가 위조하는 `x-forwarded-for` 앞값보다 우선).

#### `src/lib/bot.ts` — 봇/크롤러 추정
- **배우는 개념:** 정규식 목록으로 User-Agent를 검사. 왜 100%가 아니라 "추정"인지.
  `(?<!cu)bot\b` 같은 부정 룩비하인드로 CUBOT 폰을 봇으로 오인하지 않게 한 것도 보세요.

### 6.4 인증(로그인 대체)

#### `src/lib/secrets.ts` — 서버가 관리하는 비밀값
- **배우는 개념:** 환경변수가 있으면 그것을, 없으면 무작위 값을 만들어 DB에 저장하고
  메모리에 캐시. `upsert`(있으면 그대로, 없으면 생성)로 동시 생성 경합을 피함.

#### `src/lib/auth.ts` — 세션/쿠키/JWT (핵심)
- **배우는 개념:** JWT를 만들고(`SignJWT`) 검증(`jwtVerify`)하는 흐름, 쿠키 보안 옵션,
  익명 작업공간 자동 생성(`createGuestUserAndSession`), 토큰으로 세션 열기(`startSessionByToken`).
- **눈여겨볼 부분:** `requireUser()`가 세션이 없으면 랜딩(`/`)으로 보내는 "보호막" 역할.

### 6.5 분석

#### `src/lib/analytics.ts` — 클릭 1건에서 정보 뽑기
- **배우는 개념:** `UAParser`로 User-Agent 분석(브라우저/OS/기기), 봇 판별,
  **개인정보 보호 방문자 해시**(`computeVisitorHash`): IP+UA+날짜+비밀값을 섞어 되돌릴 수 없는
  해시로 만들고, "오늘 날짜"를 섞어 매일 값이 바뀌게 함 → 장기 추적 불가.

#### `src/lib/stats.ts` — 통계 집계 (SQL + 시간대) — 어려운 편
- **배우는 개념:** Prisma의 `$queryRaw`로 직접 SQL 실행, `COUNT`/`GROUP BY`,
  bigint→number 변환, **한국시간 변환 트릭**(UTC에 시차를 더한 뒤 날짜/시간으로 자름),
  그래프의 "빈 구간 0으로 채우기".
- **눈여겨볼 부분:** `make_interval(mins => ${off}::int)` 에서 `::int` 캐스팅이 꼭 필요한 이유
  (PostgreSQL에서 파라미터로 넘길 때 타입 지정이 필요). `genericBreakdown`이 raw SQL로
  `COUNT(*)` 기준 정렬을 해서 "값이 빈(Unknown) 그룹"이 순위에서 빠지지 않게 한 것.

### 6.6 링크 만들기와 서버 액션

#### `src/lib/links.ts` — 링크 CRUD
- **배우는 개념:** **권한 확인 패턴** `where: { id, userId }`(내 것만 찾음 → IDOR 방지),
  슬러그 중복 처리(`P2002` 고유 제약 위반), 목적지 검증을 먼저 하는 이유.
- **눈여겨볼 부분:** `updateLink`가 링크 id는 그대로 두고 값만 바꾸므로 통계가 유지되는 것.

#### `src/lib/actions/*.ts` — 서버 액션
- **배우는 개념:** 파일 맨 위 `"use server";` = 이 함수들은 브라우저에서 호출하지만 서버에서
  실행됨. `public.ts`(랜딩에서 익명 생성), `links.ts`(만들기/수정/삭제/이미지),
  `workspace.ts`(통계 초기화/전체 삭제/새 작업공간). `revalidatePath`로 캐시 갱신.
- **눈여겨볼 부분:** `createLinkAction`이 이미지 업로드 실패를 "경고"로만 처리(링크 생성 자체는
  성공으로 유지) → 부분 실패를 다루는 실무 패턴.

### 6.7 라우트(주소를 처리하는 코드)

#### `src/app/go/[slug]/route.ts` — 짧은 링크 클릭 처리 (심장부)
- [5장](#5-핵심-링크-클릭-1건의-여정-데이터-흐름)의 흐름을 코드로 확인.
- **눈여겨볼 부분:** `withRetry`(잠든 DB 재시도), `Promise.race([기록(), sleep(2500)])`
  (통계 기록을 최대 2.5초만 기다려 이동을 안 막음), 실패 시 친절한 503.

#### `src/app/d/[token]/route.ts` — 대시보드 링크로 세션 열기
- 토큰 검증 후 세션 쿠키를 심고 `/dashboard`로 이동(302). 로그인 없이 재접속하는 원리.

#### `src/app/api/*` — 데이터 API
- CSV 내보내기(`export/events`, `export/links`), QR 이미지(`qr/[slug]`),
  공개 링크 생성(`public/links`), 정리 크론(`cron/prune`), 헬스체크(`health`).
- **배우는 개념:** Route Handler(GET/POST 함수), 상태 코드, 소유권 검사, 스트림/이미지 응답.

### 6.8 화면(React)

#### 페이지들 (`src/app/**/page.tsx`) — 대부분 서버 컴포넌트
- `(marketing)/page.tsx`: 랜딩(홈). 누구나 링크를 줄일 수 있는 입구.
- `(dashboard)/dashboard/page.tsx`: 대시보드 개요(KPI + 그래프).
- `dashboard/links/page.tsx`, `.../[slug]/page.tsx`: 링크 목록·상세.
- **배우는 개념:** `async` 서버 컴포넌트에서 `await`로 DB 조회 후 화면 그리기,
  `requireUser()` 보호, `params`/`searchParams`로 주소의 값 받기.

#### 상호작용 부품들 (`src/components/**`) — 클라이언트 컴포넌트가 많음
- `public-link-creator.tsx`, `link-form.tsx`: 폼 + `useFormState`/`useFormStatus`.
- `link-row-actions.tsx`, `delete-all-button.tsx`: 드롭다운·확인 다이얼로그·토스트.
- `charts/*`: Recharts로 막대/영역 그래프.
- **배우는 개념:** `"use client"`, `useState`, 폼 제출 → 서버 액션 → 결과 토스트 → 화면 갱신.

### 6.9 다국어(i18n)

#### `src/lib/i18n/*` — 한국어/영어 전환
- **배우는 개념:** 로케일(언어) 결정 순서(쿠키 → Accept-Language → 기본값),
  서버용 `getT()`와 클라이언트용 `useT()`가 같은 `t("키")` 방식으로 문구를 꺼냄,
  사전 파일(en/ko)에서 번역 문구를 관리. 랜딩 헤더의 언어 토글이 쿠키를 바꾸고 새로고침.

## 7. 자주 나오는 문법·패턴 치트시트

이 코드에서 반복적으로 보게 될 패턴을 모았습니다.

```ts
// 1) 안전하게 값 꺼내기
const city = header ?? null;               // 없으면 null
const first = list[0]?.trim();             // list[0]이 없으면 undefined

// 2) 조건부 조기 반환 (early return): 예외 상황을 위에서 걸러내고 아래는 정상 흐름만
if (!user) return null;
if (!link) return unavailable("notfound");

// 3) 소유권 확인 (남의 데이터 접근 차단)
const link = await prisma.link.findFirst({ where: { id, userId } });
if (!link) throw new LinkError("Link not found.", 404);

// 4) 동시에 여러 개 조회 (빠름)
const [a, b] = await Promise.all([queryA(), queryB()]);

// 5) 오류를 삼켜서 부가 기능이 본 기능을 막지 않게
try { await recordAnalytics(); } catch { /* 통계 실패는 무시 */ }

// 6) 번역 문구 꺼내기 (서버/클라이언트 동일한 모양)
const t = getT();      // 서버 컴포넌트
const t = useT();      // 클라이언트 컴포넌트
t("dash.totalClicks")  // 현재 언어의 "총 클릭수" / "Total clicks"

// 7) React 상태
const [open, setOpen] = React.useState(false);   // open: 값, setOpen: 바꾸는 함수
setOpen(true);                                    // 바꾸면 화면이 다시 그려짐
```

## 9. 용어 사전

| 용어 | 쉬운 설명 |
|---|---|
| **슬러그(slug)** | 짧은 주소의 끝부분. `/go/abc123`의 `abc123`. |
| **리다이렉트(redirect)** | 다른 주소로 자동으로 보내는 것(상태코드 302). |
| **서버 컴포넌트** | 서버에서 실행되어 데이터를 불러와 화면을 그리는 React 부품. |
| **클라이언트 컴포넌트** | 브라우저에서 실행되어 클릭·입력에 반응하는 부품(`"use client"`). |
| **서버 액션** | 버튼/폼이 호출하지만 실제로는 서버에서 실행되는 함수(`"use server"`). |
| **ORM / Prisma** | DB를 SQL 대신 일반 코드로 다루게 해 주는 도구. |
| **쿠키(cookie)** | 서버가 브라우저에 저장해 두는 작은 값(자동으로 다시 딸려 옴). |
| **세션(session)** | 로그인 상태 같은 것. 이 앱은 JWT를 쿠키에 담아 표현. |
| **JWT** | 서명이 붙은 토큰. 비밀 키로만 만들 수 있어 위조를 막음. |
| **해시(hash)** | 값을 되돌릴 수 없는 고정 문자열로 바꾸는 것. 방문자 추정에 사용. |
| **UTM** | 방문 출처를 URL에 표시하는 표준 태그(utm_source 등). |
| **SSRF** | 서버가 내부 주소로 요청하게 속이는 공격. url.ts가 방어. |
| **XSS** | 남의 브라우저에서 악성 스크립트를 실행시키는 공격. |
| **IDOR** | 남의 데이터 id를 넣어 접근하는 취약점. `where: { id, userId }`로 방어. |
| **속도 제한(rate limit)** | 같은 사람이 너무 자주 요청하지 못하게 막는 것. |
| **봇(bot)** | 사람이 아닌 자동 프로그램(크롤러, 미리보기 생성기 등). |
| **UTC / KST** | 세계 표준시 / 한국시간(UTC+9). |
| **비동기 / async·await** | 시간이 걸리는 일을 "기다렸다가" 결과를 받는 방식. |
| **환경변수** | 코드 밖(서버 설정)에 두는 값. 비밀번호 등. `process.env`로 읽음. |
| **i18n** | 국제화. 여러 언어(한/영)를 지원하는 것. |
